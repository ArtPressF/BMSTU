# Лабораторная работа №2. Ввод-вывод в файлы

Выполнил: Мустафаев Артур Эльдарович, группа ИУ8-14/6. Вариант 18.

## Цель работы

Овладеть навыками разработки программ на языке Си++, использующих ввод-вывод в файлы.

## Условие

Структура «компьютер» (поля: тип процессора, тактовая частота, объем оперативной памяти, размер жесткого диска, тип видеокарты). Создается массив (вектор) компьютеров размерности n. Он сохраняется в файле и читается из файла в текстовом и двоичном режимах. Нужно сравнить размеры двух файлов с данными. Использовать шаблон `vector` и класс `string`. Режимы приложения задаются параметрами командной строки: сначала чтение (`read`) или запись (`write`), затем текстовый (`text`) или двоичный (`binary`) режим, затем имя файла. Для чтения и записи структурной переменной использовать функции.

## Решение

Программа: [computers.cpp](computers.cpp). Она построена по образцу примера со структурой «книга» из методического файла.

Структура `COMPUTER` содержит поля: `cpu` (тип процессора, `string`), `freq` (тактовая частота в ГГц, `double`), `ram` (объем оперативной памяти в ГБ, `int`), `disk` (размер жесткого диска в ГБ, `int`), `gpu` (тип видеокарты, `string`). Массив компьютеров хранится в `vector<COMPUTER>`.

Параметры командной строки (`argc`, `argv`) задают режимы работы, например:

```
computers write text MyFile.txt     запись, файл в текстовом режиме
computers write binary MyFile.dat   запись, файл в двоичном режиме
computers read text MyFile.txt      чтение, файл в текстовом режиме
computers read binary MyFile.dat    чтение, файл в двоичном режиме
```

Если параметров не три, режим работы или режим открытия файла указаны неверно, выводится сообщение об ошибке в `cerr`, а программа завершается с кодом 5. Если при чтении файл не найден (проверка `!` после открытия потока), выводится `Error, file not found`, а программа завершается с кодом 1. Перед чтением данных программа определяет размер файла функциями `seekg` и `tellg` и проверяет прочитанное число `n`: если файл пустой, записан в другом режиме или поврежден (число `n` не прочиталось, оно отрицательное или больше размера файла, либо данные закончились раньше времени), выводится `Error, wrong file format`, а программа завершается с кодом 1.

**Режим записи.** С клавиатуры вводится число компьютеров `n` и данные каждого компьютера. Строки с пробелами читаются функцией `getline`, а перед ней символ перехода на новую строку, оставшийся после числа, пропускается функцией `ignore`. Введенные данные выводятся на консоль для контроля, затем записываются в файл.

**Функции для обмена с файлом** (для одной структурной переменной), отдельные для двух режимов:
- `write_text` и `read_text` — текстовый режим;
- `write_binary` и `read_binary` — двоичный режим;
- `print_computers` — печать массива компьютеров в поток (на консоль).

**Формат текстового файла.** Первая строка — `n`. Затем для каждого компьютера: строка с типом процессора, строка с типом видеокарты, строка с тремя числами через пробел (частота, память, диск). Строки записываются с новой строки (`endl`), числа читаются операцией `>>`, а перед чтением строк пропускаются символы перехода на новую строку (`ignore`).

**Формат двоичного файла.** Вначале `n` (4 байта). Затем для каждого компьютера: тип процессора и тип видеокарты, после каждой строки записывается нулевой байт (манипулятор `ends`) как признак конца строки, затем `freq` (8 байт), `ram` (4 байта), `disk` (4 байта). Числа записываются функцией `write` в том виде, как они хранятся в памяти, и читаются функцией `read`, строки читаются функцией `getline` с ограничителем `'\0'`.

|---|---|---|---|---|

CPU: AMD Ryzen 5 5600X, 3.7 GHz, RAM 32 GB, disk 1000 GB, GPU: AMD Radeon RX 6600
CPU: Intel Core i3-10100, 3.6 GHz, RAM 8 GB, disk 256 GB, GPU: Intel UHD Graphics 630

**Размеры файлов** (Windows, в текстовом режиме каждый перевод строки занимает 2 байта):

| Набор данных | Текстовый файл, байт | Двоичный файл, байт |
|---|---|---|
| Таблица выше (короткие числа: частота `3.6`) | 169 | 176 |
| Частоты вида `5.8`, `4.5`, `2.5`, память 128, 64, 32, диск 4000, 2000, 1000 | 178 | 181 |

## Выводы

- Данные, сохраненные в текстовом и в двоичном режимах, читаются одинаково: на консоль выводятся одни и те же значения.
- Размер двоичного файла почти не зависит от значений чисел: `n` занимает 4 байта, а каждый компьютер — длину двух строк плюс по одному нулевому байту на строку и 16 байт на числа (8 байт `double` и два `int` по 4 байта).
- Размер текстового файла зависит от того, сколько символов занимают числа, и от переводов строк (по 2 байта на каждую из трех строк компьютера). Для коротких чисел (`3.6`, `16`, `512`) текстовый файл получается чуть меньше двоичного (169 против 176 байт), для чисел с большим числом цифр (`5.8765`, `4000`) — больше (187 против 181 байта).
- Двоичный режим удобен тем, что записанные числа не теряются при чтении и все записи имеют предсказуемый размер чисел, а текстовый файл можно открыть и проверить в любом текстовом редакторе. По умолчанию в текстовом режиме `double` записывается с шестью значащими цифрами, в двоичном режиме — точно.
