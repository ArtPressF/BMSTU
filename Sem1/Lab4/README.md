# Лабораторная работа №4. Использование объектов своих классов в последовательных контейнерах STL

Выполнил: Мустафаев Артур Эльдарович, группа ИУ8-14/6. Вариант 18.

## Цель работы

Научиться хранить объекты своего класса в последовательных контейнерах библиотеки STL (`list`, `vector`, `deque`), копировать контейнеры алгоритмом `std::copy` и сортировать их.

## Условие

Вариант 18 по таблице 1: объект «автомобиль» (поля: название модели, массив расходов топлива из трех элементов (на трассе, в городе, смешанный), максимальная скорость, мощность). Сортировка по названию модели. Исходный контейнер `list`, копируем в `vector`.

Элементы контейнеров должны быть объектами класса, а не указателями. Класс должен иметь нужные конструкторы, при необходимости конструктор копирования и перемещения и операции присваивания с копированием и перемещением (наличие или отсутствие нужно обосновать) и перегруженную операцию вставки в поток `<<`. Нужно скопировать один контейнер в другой алгоритмом `std::copy` и отсортировать исходный контейнер: для `list` методом `list::sort` без параметров. Исходные данные читаются из `input.txt`, в `output.txt` выводятся исходный контейнер, контейнер после сортировки и контейнер, в который скопирован исходный.

## Решение

Программа: [cars.cpp](cars.cpp).

Класс `Car` хранит название модели (`string`), расход топлива в массиве из трех `double`, максимальную скорость и мощность (`int`). У него два конструктора: без параметров (он нужен, потому что вектор для копирования создается сразу нужного размера) и конструктор, который задает все поля. Операция `<` сравнивает автомобили по названию модели, поэтому `list::sort()` без параметров сортирует именно по названию. Операция вставки в поток `<<` определена вне класса и объявлена дружественной, чтобы читать закрытые поля.

Конструктор копирования, конструктор перемещения и операции присваивания я не писал. В классе нет указателей и динамической памяти, а `string` и массив из трех чисел компилятор копирует и перемещает правильно сам. Для проверки в конце программы объект копируется конструктором копирования и присваиванием, и обе копии совпадают с оригиналом.

Данные читаются из `input.txt`: сначала число автомобилей, потом для каждого название модели отдельной строкой и следом строка с пятью числами (три расхода, скорость, мощность). Автомобили кладутся в `list<Car>`. До сортировки содержимое копируется в `vector<Car>` алгоритмом `copy`, так что вектор хранит исходный порядок. Потом выполняется `cars.sort()`. В `output.txt` выводятся три контейнера, каждый через перегруженную операцию `<<`.

В исходных данных название «Audi A4» встречается дважды: это показывает, что `list` и `vector` хранят все объекты, и что при равных названиях сортировка сохраняет их прежний порядок.

## Выводы

`list` с методом `sort()` без параметров сортирует объекты, если у класса есть операция `<`. Алгоритм `copy` копирует объекты в контейнер другого типа, но принимающий контейнер должен уже иметь нужный размер, а у класса должен быть конструктор без параметров. Когда класс не владеет динамической памятью, собственные конструкторы копирования и перемещения не нужны: достаточно тех, что создает компилятор.
